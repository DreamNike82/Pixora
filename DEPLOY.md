# Деплой Pixora (фронтенд)

## Як це працює
Фронтенд звертається до `/api/...` на власному домені, а хостинг (rewrite) перенаправляє ці запити на
`https://pixora-ashy-iota.vercel.app`. Для браузера це same-origin: CORS не потрібен, сесійна кука працює.

- `VITE_API_URL` залишайте **порожнім** (і локально, і на хостингу).
- Vercel: `vercel.json`. Netlify: `netlify.toml`. Обидва містять і проксі `/api`, і SPA-fallback.
- Збірка: `npm install && npm run build` → папка `dist`.

## Чекліст перед запуском
1. Бекенд: Stripe success/cancel URL ведуть на новий домен (сторінка тарифів очікує `?checkout=success` або `?session_id=`).
2. S3: у CORS бакета дозволено `PUT` з нового домену (великі файли йдуть напряму в S3 через presigned URL).
3. Після деплою перевірити: реєстрація → вхід → оновлення сторінки на `/dashboard` (не має бути 404) →
   створення галереї → завантаження фото → відкриття `/g/<token>` в анонімному вікні.

## Прямі запити до бекенду (не рекомендовано)
Якщо задати `VITE_API_URL=https://pixora-ashy-iota.vercel.app`, власник бекенду має додати ваш домен у CORS
і віддавати куку з `SameSite=None; Secure`. Значення вшивається в збірку, тому після зміни потрібен новий білд.
